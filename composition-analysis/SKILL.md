# 构图分析（21 类判断卡 + 本地工作台）

把「21 类判断卡」「公开许可与 AI 原创参考图库」「本地构图网页」连起来：**用户给图 → 按判断卡判读 → 生成能在网页里看的标注结果与参考案例 → 用途建议单独给**；用户要求时，再依据图像可见内容反推生图提示词。

这是供 AI 助手执行的视觉判读流程，**不是网页引擎的自动识别**。网页内置引擎仍只有 17 类规则；第 18–21 类由 Skill 视觉判读给出，必须在结果里如实标明（渲染器会自动打标）。判断规则、结果 JSON 和 Python 渲染器尽量保持通用；具体 AI 工具是否能读取图片、访问本地文件并运行 Python，取决于宿主工具能力。当前静态网页没有连接任何 AI 服务。

## 一、开始之前（每次都做，不要凭记忆）

1. 读 `config.json`，拿到 `workspace_root` 与各资产路径。主工作台是 `构图分析工作台.html`：它整合「最新判读 / 参考图库 / 工具说明 / 图片分析 / 关于我」五页，默认打开「最新判读」；关于我页展示作者介绍、微信搜索图和日常照片。图库已整合在同一工作台，不需要再打开独立静态图库页。当前公开版在「最新判读」页保留一批 8 张由作者确认可公开展示的静态案例；它们只是示例数据，不代表网页自动调用 AI。以后新增公开案例仍须先确认素材权利。
2. 读这三份**现行口径**，以文件内容为准，不要凭上一轮对话记忆：
   - `cards_md` / `cards_json`：21 类判断卡（定义、画面证据、易混、**不能判成这一类的情况**、图库编号）
   - `sop_md`：真实图片分析流程 SOP（判读七步、四层标签、用途比较规则）
   - `taxonomy_json`：21 类体系与辅助标签；本整合包将它指向同一份 21 类判断卡 JSON，避免重复口径
3. 读 `assets/gallery/gallery_manifest.json`（168 张图例清单），**只用来按编号查案例元数据、来源、作者与许可条件**，不要按标题分类；图片文件位于 `assets/gallery/`。
4. 确认 `engine_html` 存在。它**只读**，任何情况下都不覆盖、不修改。

## 二、向用户确认输入

| 项 | 要求 |
|---|---|
| 图片 | 消息附件、本地绝对路径，或用户放进某个目录后给出目录名。JPG/PNG/WEBP 均可，短边建议 ≥ 700px。一轮 1–8 张 |
| 用途（可选） | 文章封面 / 内容首图 / 商品细节图 / 其它。**没给就不替用户定用途**，只做条件性比较 |
| 已知信息（可选） | 是否要留压字空间、横竖版等。只影响用途建议，不影响构图判定 |
| 反推设置（可选） | 是否反推生图提示词、目标生图工具、忠实复现/保留主体换场景/只借构图，以及必须固定或允许修改的内容 |

如果当前对话无法读取待分析图片，说明图片不可见并请用户重新上传；若用户只要求先起草，必须标明是待图片校准的通用草稿。不要根据文件名、简短描述、参考图库、历史图片或上一轮测试图伪称观察到构图。

> **网页与 AI 的边界**：本地静态网页的上传／拖入只由网页自己的旧规则引擎处理，不能因此推断某个 AI 助手会收到图片或被调用。当前工作台没有 browser bridge、API 或本机 AI 连接器；浏览器图片不会自动进入 AI 对话或工作区。所以：
> - 网页「放图／拖入／粘贴」只跑旧 17 类规则，结果标「规则检测参考」；
> - Skill 视觉判读需由宿主 AI 对话中的图片附件，或 AI 可访问的本地绝对路径触发；
> - 只有当目标 AI 工具支持图片输入、读写工作区和运行 Python 时，才能完整执行渲染流程；仅支持聊天的工具可复用判断卡，但不能声称已生成本地工作台；
> - 每次都如实说明边界，不能把静态结果面板说成「网页已连接 AI」或「网页已能做 21 类自动识别」。

## 三、判读（只按画面）

1. 先看整幅，确认单幅实拍 / 海报版式 / 多图拼贴，版式图要额外说明版式影响。
2. **先用判断卡「不能判成这一类的情况」做减法**，再看证据是否齐备，选证据最强、能解释整体组织方式的一类。
3. 文件名、目录名若含构图类别字样或旧标注，**一律不作为分类依据**；若标签在判读前已可见，要在结果里如实说明，不要虚称「严格盲判」。
4. 每张输出：主构图 1 个 + 把握度；辅助结构**最多 3 个**（各标强度）；画面位置证据；易混类别与排除理由；不确定项。
5. 弱证据写「弱辅助证据」并说明由哪条线支持；类别重叠写清「若按 A…若按 B…」和倾向；证据不足写「不确定 / 不判」，**不为凑满 21 类硬判**。
6. 四层标签分开：构图结构 / 题材 / 拍摄属性 / 设计版式。**拍摄角度一律写「未标注」**，不从平铺、透视或明暗反推相机角度；不从画面推断光源方向当角度证据。
7. 不从「平铺构图」反推俯拍；黄金比例无可见螺旋或可核对 Phi 网格时不判。

## 四、案例对照（初判完成之后才做）

- 每张**最多 2 张**，只按画面挑，保留编号。
- 结果 JSON 里案例只写 `num`（编号）、`similar`（相似点）、`different`（不同点）；**主构图、来源类型、作者、许可、来源链接与图片文件一律由 `render.py` 从 manifest 精确读取**，agent 不要自己填，避免臆造。
- 没有合适案例就写 `"cases": []`，并在 `case_note` 说明「本图无合适图库案例，未硬配」或「只做结构形态对照」。不要拿别类凑数。
- 图库来源分两类：123 张 Wikimedia Commons 图片逐图显示作者、来源页与 CC／CC0／公有领域等许可；45 张标为「项目 AI 原创教学示意」，不标作 CC 授权图片。凡复用 Commons 图片，必须遵照该图卡片链接的具体许可条款。

## 五、用途建议（与构图判定分开写）

- 用户给了用途：只按该用途给结论 + 画面事实依据（主体占比、可压字空域、边缘裁切、背景干扰、横竖版），指出其它图在该用途下的短板。
- 用户没给用途：`usage.given` 写「未指定用途（条件性比较）」，`alternatives` 每种用途各自给结论，**不合并成总排名**。
- **不推断具体平台的电商主图合规要求**（白底、无遮挡、完整陈列等需在平台规则下另行核对）。若挑商品图，只能写「这几张里较适合突出某细节」。
- 「有可压字空域」属用途／版式层，「留白构图是主结构」属构图结构层，两者不能互相推导。已有大标题的图，剩余空域写清只适合小副标题，不要写成还有大块压字空间。

## 六、反推生图提示词（用户提出时执行）

用户说「反推提示词」「看图写 prompt」「照这个画面做一张」「帮我复刻风格」时，读取 `references/反推提示词指南.md` 和 `references/model-neutral-prompt-spec.md`，根据用户上传的原图直接完成视觉拆解与提示词，不把网页里的旧规则结果当作视觉理解。

1. 将当前 AI 对话工具（宿主）与用户想用来生图的工具（目标工具）分开记录。优先使用用户明确指定的目标工具；未指定时，默认交付一份 GPT 友好的详细中文版本和一份不依赖专有语法的跨平台通用版本。若当前宿主或具体模型名称不可见，写「当前环境未暴露具体模型」，不得猜测或声称自动检测到了隐藏模型。
2. 默认采用「忠实重建视觉效果」：保留图片可见主体、身份特征、主体数量、主要构图关系、主体位置与比例、视角、光线、色彩和质感。用户若要求换主体、换场景或只借构图，按用户要求重设固定项和可改项。
3. 明确提示词是根据可见画面重建的**新提示词**，不是原作者真实 prompt，也不能保证不同模型生成完全相同的结果。只描述图中有证据的内容；不编造品牌型号、镜头参数、不可见场景或原始生成工具。
4. 输出固定项清单、可改项清单、GPT 细致版、跨平台通用版、可选负面约束。每个可改项给当前默认值和替换建议；例如主体、场景背景、画幅比例、风格强度、文字、配色、道具。保持项不得被可改项覆盖，若用户要求改动则明确调整对应项。
5. 用自然语言描述主体、画面布局和坐标关系、机位与景别、背景层次、光线方向与软硬、色彩、材质、风格、细节密度、画幅及边缘裁切。GPT 版可充分展开并写清「保留／不要改变」约束；通用版保留同一画面事实，避免模型专属权重、参数、语法。只有用户指定目标平台并且需要平台专属参数时，才查证该平台当前官方语法；不要凭印象添加参数。
6. 多格拼图先确认行列数与每格画幅。若有 `C` 列、`R` 行、单格宽高比 `r=宽/高`，且格子等大、无额外留白，则整体宽高比为 `(C/R)×r`。用户给出的规格冲突时先指出并给出可执行选项，不将矛盾比例同时写进提示词。每一格分别描述机位、动作、景别和主体位置；共享角色/商品特征另列为连续性锚点。
7. 将工具自动添加的水印记录为来源标记，默认不写入创作提示词。文字提示不能保证移除平台自动水印；需要无水印文件时查看平台正规导出选项。
8. 如果用户只要提示词而当前 AI 无法访问项目文件或运行 Python，直接在对话里交付提示词，不要因此中断。如果宿主能写项目文件且用户也需要在工作台查看，将结构化提示词放进每张图的 `reverse_prompt` 字段，由渲染器在「最新判读」显示可编辑变量和可复制版本。
9. 不要仅因用户上传了图片就自动执行反推；只有用户明确提出反推或在请求中包含该意图时才生成提示词。也不要自动替用户调用生图模型；生成图片必须是用户另行提出的目标。

具体输出字段及占位符形式见 `references/反推提示词指南.md` 和 `references/字段说明.md`。

## 七、标注坐标（用于网页画图）

`annotations` 用**归一化 0–1 坐标**，是看图时的**近似示意**，不是测量数据：

```json
"annotations": {
  "subject_box": [0.35, 0.12, 0.63, 0.88],
  "lines": [{"from": [0.0, 0.85], "to": [0.95, 0.25], "label": "车轮阵列斜线"}],
  "regions": [{"rect": [0.0, 0.70, 1.0, 1.0], "label": "下方较干净区域", "type": "negative"}]
}
```

- `subject_box`：主体大致范围；`lines`：构图线（只画真正承担结构作用的线）；`regions`：留白或关键结构区域。没有就把对应数组留空。
- 每张必须写 `annotation_note`，说明这些框线是视觉估计、对应画面里哪条线／哪块空域。渲染器会在网页上统一标注「视觉估计示意标注，不是网页引擎自动检测结果」。

## 八、写结果 JSON 并渲染

把结果写到 `config.results_dir/最新结果.json`（结构见 `references/结果JSON模板.json` 与 `references/字段说明.md`），然后运行：

```bash
python "<SKILL目录>/scripts/render.py" --result "<workspace_root>/构图分析_结果/最新结果.json"
```

渲染器会：
1. 校验 JSON（字段、辅助结构 ≤3、案例 ≤2、角度「未标注」、案例编号存在于索引、原图存在）；
2. 画标注图（橙=主体框，蓝=构图线，绿虚线=留白/结构区域）；
3. 内嵌原图、标注图、案例图，从索引补齐来源类型；
4. **只读** `engine_html`，把结果面板注入 `</body>` 前，写出 `workbench_html`（新版本副本，原网页不动）；**并把「面板默认展开 `class="on"`」与「规则检测参考」徽标静态写入 HTML**，不依赖运行时脚本（2026-11-12 修正：此前只靠脚本末尾 `classList.add('on')`，用户在预览里需要手动点按钮）；
5. **把最新判读设为主工作台首页，并整合完整图库**：`build_library_html()` 读取包内 manifest，将参考图压缩成 data URI 内嵌为静态卡片。顶部导航顺序为「最新判读 / 参考图库 / 工具说明 / 图片分析 / 关于我」，默认打开「最新判读」并显示当前结果 JSON 中的批次；没有结果时显示空状态，不得用图库页冒充判读结果。后续新判读须先写入 `最新结果.json` 并运行渲染器，静态网页不会自动接收 AI 对话结果。图库保留搜索、21 类筛选和来源筛选，点击图片用页内弹层看大图（关闭按钮、点背景或 Esc 均可关闭）。案例按钮切到图库并高亮对应编号。**参考图需留在同一个主工作台内，不要求用户再打开独立预览页。作者头像、署名、关于我文案与图片以内嵌方式写入；二维码图保留原始像素，避免重压缩影响扫码。**
6. 图库的类名 / ID 一律加 `lib` / `sk` 前缀，CSS 限定在 `#skPageL` 内，避免与原网页已有的 `.card` / `.row` / `.note` / `#zoom` 冲突；不要把两个完整 HTML 文件硬拼在一起。
7. 归档结果 JSON 到 `results_dir/<时间戳>.json`。

渲染完成后确认「最新判读」是默认页、图库仍内嵌在同一工作台、案例编号能对应当前 manifest。网页只展示写入的静态结果；不要把默认进入最新判读写成网页能自动调用 AI 或自动接收对话结果。

最后用 `present_files` 打开 `workbench_html`，并在回复里给逐张结论摘要、案例来源类型统计、用途建议，以及「网页仍只有 17 类，第 18–21 类为 Skill 判读；静态网页未连接 AI 服务」的边界说明。

## 九、硬边界（写进每次回复）

1. **知识库有 21 类 ≠ 网页已能自动识别**。网页引擎 17 类；第 18–21 类（非对称均衡、放射／径向、黄金比例／黄金螺旋、透视汇聚／消失点）由 Skill 视觉判读，网页结果里会打「Skill 视觉判读 · 网页引擎未支持该类别」标签。
2. 本流程是人工／视觉判读，**不涉及网页自动识别准确率**，也不验证网页输出。
3. 参考图数量、类别数量不能当识别准确率。
4. 不修改底层 17 类识别阈值；本轮不采集新的外部图片，不把用户图片加入知识库或图库。
5. 拍摄角度自动识别已停用，角度只写「未标注」。
6. 案例来源、作者与具体许可按 manifest 如实写；Commons 许可可能要求署名或相同方式共享，AI 原创教学图不标作 CC 授权。
7. **网页上传不触发 Skill**：本地静态网页上传只跑旧 17 类规则；当前网页没有连接任何 AI 服务。旧规则结果必须标「规则检测参考」，与 Skill 判读分开。
8. **只写当前批次**：`最新结果.json` 的 `images` 只能包含本次用户提交的图片，不得沿用其他批次或预制 JSON；渲染前确认标题、批次说明、图片 id 与本次输入一致。公开发布该批结果前，先确认每张输入图适合公开展示并有相应权利。
9. **图库整合 ≠ 面板能弹出**：验收必须确认同一个 HTML 里能切到 168 张图库、搜索／21 类筛选／来源筛选都生效、案例卡能跳到当前 manifest 中的编号，且 168 张图能离线显示；只验证面板展开不算完成。
10. **工具通用性有边界**：判读规则与结构化结果可供不同 AI 助手复用，但本地渲染要求宿主能读图、访问项目文件并运行 Python；不要声称已在未验证的工具中安装或端到端跑通。
11. **保护能力如实说明**：SHA-256 清单用于发现文件变化，不阻止修改，也不是数字签名；清单须独立保存。核心规则随本地 Skill 文件交付时可被读取和复制；如需隐藏需迁移到有账号验证的服务端，不能承诺绝对防逆向。
12. **模型适配边界**：按当前对话里可见的宿主能力和用户指定的目标生图工具组织提示词；静态网页不能侦测用户正在使用的其它 AI 客户端或其隐藏模型，也不能直接控制它。未指定目标时提供 GPT 细致版与跨平台通用版。
